# R01 · Breakpoint tokens (responsive groundwork)

Source: Figma "bs internal tools" › CIR · Design System › Breakpoint variables + *Pattern · Responsive* + docs "11 / Responsive & mobile".

| Set | Range | Cols | Margin | Gutter | Header | Control / input | Input text |
|---|---|---|---|---|---|---|---|
| desktop | ≥ 1280 (ref 1440) | 12 | 32 | 24 | 78 | 32 / 36 | 13 |

## What `npm run tokens` now emits
- `--breakpoint-tablet: 48rem`, `--breakpoint-desktop: 80rem` → Tailwind variants `tablet:` `desktop:` `max-tablet:` `max-desktop:` (no `sm/md/lg`; the theme is cleared).
- **Desktop-first:** write the 1440 class, override below with `max-desktop:` (tablet + mobile) or `max-tablet:` (mobile). Nothing at ≥ 1280 changes.
- Component sizes are re-pointed per breakpoint in `@media (width < 80rem)` / `(width < 48rem)`: `--spacing-control-height`, `input-height`, `search-height`, `layout-header-height`, `layout-gutter` (= margin), `layout-rail-width`, plus `--input-font-size`, `--grid-columns`, `--grid-gutter`. Existing classes (`h-control-height`, `px-layout-gutter`…) follow automatically.
- The generator throws if a component token's desktop value drifts from the Breakpoint desktop value.
- Column counts are unitless (`--spacing-desktop-columns: 12`).
- `--safe-area-bottom: env(safe-area-inset-bottom, 0px)`; `app/layout.tsx` exports `viewport` with `viewportFit: "cover"`.
