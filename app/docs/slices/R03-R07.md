# R03–R07 · Mobile build (below 768)

Designs: `R02.md` (Figma M01–M07, ME1–ME4, ML1–ML3, MS1–MS3, MA1–MA5, MP1–MP8). Tokens: `R01.md`.
Desktop (≥ 768) is unchanged — every change is behind `max-tablet:` / `tablet:` classes or `useIsMobile()`.

## New DS pieces
- `ds/BottomSheet.tsx` — Mobile/Bottom sheet: handle, Heading/Module title + 44 ×, scrolling content, optional sticky
  `actions` (Mobile/Action bar), safe-area bottom, scrim 54 %, Esc / scrim / × / swipe-down close, focus trap.
  `ActionBar` — sticky bottom bar (44 buttons share the width, safe area under).
- `ds/useBreakpoint.ts` — `useIsMobile()` (matchMedia `width < 48rem`), only where the component itself differs.
- `motion.css` — `.motion-bottom-sheet` (rises from the bottom edge; reduced motion → fade), `--sheet-from-y`.
- Tokens: `--text-ui-input` follows the breakpoint (13 / 14 / 16 — every field's value text, no iOS focus zoom);
  `--safe-area-bottom` = max(Figma 34 on mobile, device inset).
- `Icon/sliders-horizontal` added to the icon export (`specs/F01-icons.json` → `npm run icons`).
- Dialogs: every `Dialog` sits on the bottom edge, full width, below 768; `FormModal` / `PanelModal` render as a
  `BottomSheet` (title row + equal-width footer buttons; FormModal's start slot gets its own row).
- `InlineInput` height → `h-input-height` (36 desktop / 44 mobile).

## Known differences from Figma (by decision)
- Field value text is 16px / fields 44 high in code; CIR Input field in Figma is 36 / 13 (no mobile size in the DS) —
  gates mask field text.
- M03 Figma shows the agenda already scrolled to Today; the gate covers the header region only.
- Figma M04 draws the progress bar at ~60 %; code draws the real 40 %.
- Picker sheets for Booking date / Crew / Package (M02) aren't drawn in Figma — standard option-list sheets.
- Custom date ranges stay desktop-only (mobile offers the presets).
- Not done: tablet-specific layouts (768–1279 use desktop layouts with tablet tokens); canceled full page
  `/bookings/[id]` (BookingReadOnly) has no mobile pass yet — the mobile flow reaches canceled bookings through the
  detail sheet (ME3).
