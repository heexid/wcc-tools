## What changed

| Area | Change |
|---|---|
| **Route guard** | `src/proxy.ts`, Next 16 proxy, Node runtime. Every page request refreshes the session with `getUser()`. No session → `/login?next=<page>`. A session that existed but can't be used → `/login?next=…&expired=1` (E4, email prefilled). Server Action POSTs are never redirected. Does nothing on the mock source. |
| **Revocation** | `getUser()` rather than `getClaims()` because it asks Supabase Auth, so a session revoked by "other devices were logged out" (US-13) is refused on that device's **next page load**. Cost: one auth request per navigation (P11 measures it). **Limit:** that device's direct API reads still work until its access token expires (`jwt_expiry`, default 1 h). |
| **Open redirect** | Login `?next=` was passed to `router.replace` unchecked. `src/lib/safe-next.ts` allows only same-site paths: rejects `https://`, `//`, `/\`, control characters, and `/login` loops. 11 unit tests; proxy redirects use it too. |
| **Who is staff** (migration 005) | A profile, and with it any read access, exists only for an account an admin gave a role in `app_metadata.role`, which users can't set. The 003 read policies are replaced by `using (public.is_staff())`. A self-registered account (even with `role` in its own user metadata) gets no profile and reads nothing (pgTAP 007). New staff are created through the admin path (P14). |
| **Login errors** | E1 / E2 client-side as before. E3 for wrong credentials (generic: no account enumeration). E6 when unreachable. **Rate limit (HTTP 429): shown as E3 for now**, kept as a separate `rate_limited` code; the copy decision is below. |
| **Seed users** (local / CI only) | Admin, viewer, plus `account-test@bs-moment.test` used only by the e2e password test. Provisioned through `app_metadata.role` like real accounts. |

## Decisions (2026-11-16, user)

1. **Rate-limited sign-in:** no new copy needed. A 429 keeps showing E3 (`rate_limited` stays a separate code in the action, unused by the UI).
2. **Sessions end at 00:00 WIB every day** (replaces the "shorter `jwt_expiry`" question). Enforced in three places:

   | Where | How |
   |---|---|
   | Proxy | On the next page load after midnight, a session whose sign-in time (earliest JWT `amr` timestamp, which survives refreshes) is before today's 00:00 WIB is signed out → E4 |
   | Database (migration 006) | `session_fresh()` gates `is_staff()` / `is_admin()`, so a pre-midnight access token can't read or write through the API either. This closes the "until token expiry" window. |
   | Open tab | `AppShell` timer signs out at 00:00 and shows E4 (Supabase source only; the prototype keeps you signed in) |

   Tests: 5 unit (`session-day.test.ts`, incl. the hours when UTC is still on yesterday), pgTAP 008 (7), e2e (fake browser clock past midnight → E4, and the session is really gone). Assumed **WIB** because it is the studio clock the app already uses for "today".
3. **D3** still open: the role currently comes from `app_metadata.role`.

## Code review of P4 + P5 (2026-11-16, report-only, fixed by hand)

All 10 findings were real; 9 fixed, 1 covered as far as possible:

| # | Finding | Fix |
|---|---|---|
| 1 | Midnight `setTimeout` pauses while the laptop sleeps | Also compares the wall clock on wake / focus and every 30 s |
| 2 | Proxy skipped the guard for any request with a `next-action` header (GETs too) | Exemption only for `POST` + header |
| 3 | An Auth outage (5xx / unreachable) sent valid sessions to E4 | Transport / 5xx errors let the page load; the database still enforces access |
| 4 | Offline logout left the auth cookies | `logout()` always also clears the browser session (`signOut({scope:"local"})`) |
| 5 | Password re-check created a new session on this device; 429 showed as "incorrect" | Verified on a throwaway client (its session revoked at once); 429 / 5xx → connection error |
| 6 | Role changed after the account exists never reached the profile; demotion left admin | Migration 008: trigger on `app_metadata` updates; removal sets `profiles.active = false` (history keeps the name); pgTAP 009 (7) |
| 7 | Midnight e2e only exercises the client timer | Unit tests now cover the proxy's token decode + decision; DB rule in pgTAP 008. A server-clock e2e isn't possible without faking server time. |
| 8 | Proxy made a second Auth request just to read `amr` | `amr` decoded locally from the access token `getUser()` just validated |
| 9 | RLS called `is_staff()` per row | Policies use `(select public.is_staff())` (initPlan, once per query) |
| 10 | Auth-cookie pattern copied in 3 places | One definition: `src/lib/supabase/cookie.ts` |
