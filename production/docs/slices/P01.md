## Schema decisions (not 1:1 with the PRD text — check these)

1. **Derived columns are always recomputed.** `bookings_derive()` runs BEFORE every insert / update on `bookings` and overwrites `total`, `total_paid` and `status` from the child rows. Items / invoices fire it on the parent through a no-op update. A client cannot store a wrong total, even with direct table access.
2. **`updated_at` moves only on a real edit**, not on a recompute (an invoice insert does not change it). P7's optimistic concurrency should use this or add a `version` column. Decide then.
3. **DB backstops beyond the PRD list:** `check (total_paid <= total)` (rule 10 and overpayment), `check ((status = 'canceled') = (canceled_at is not null))`, canceled cannot be reverted, no invoice on a canceled booking, `ref` never changes, bookings cannot be deleted (US-12 "There's no delete"), invoices cannot be truncated. The full rule 8 amount checks and rule 12 / 13 transitions stay in the P2 RPCs.
4. **`booking_counters`** is a new table beside `invoice_counters`. The ref year is the creation year in Asia/Jakarta (same as the prototype's `today()`).
5. **`created_by` / `canceled_by` / `updated_by` are `uuid → profiles`**, null in the seed (the prototype stores the text "Admin"). P4 must create the seed admin user and decide whether to back-fill.
6. **Limits only where the prototype or PRD has one:** client name 2–80 (trimmed), phone in `normalizePhone()` form `+62…`, terms / cancel reason ≤ 255, description ≤ 1000, display name 2–50, payment instruction per `PAYMENT_LIMITS`, business info per US-14. Package / crew / item / booking names have no max (the prototype has none). Caps on free text are left for P10.
7. **RLS is enabled on every table now, with no policies.** Anon and authenticated get nothing until P4 / P10, so a misconfigured API key exposes nothing. `next_booking_ref` / `next_invoice_number` are revoked from `public`, `anon` and `authenticated`.
8. **`workspace_settings` is created now** (PRD §4.2) and seeded with the prototype's business, terms and payment. D4 (where bank / terms really come from) is still open; P8 may move those two columns' source.
9. Seed ids are deterministic UUIDs (md5 of the prototype id), so seeded rows keep stable ids across resets.

## Open (blocks "Done")

2. **Generated types.** `src/lib/db/database.types.ts` is not committed: `supabase gen types` needs the local stack. The CI step writes it and fails on a diff, so the first CI run will fail until the file is committed from that output.
3. **Review** (§1 step 6): `code-review` not run on P0 or P1.
4. "Compare seed totals with `/dev/data`" (workflow step 8) is covered by `005_seed_parity` rather than by eye.

## Rollback

Nothing is deployed. Locally: delete the migration and the seed. Once applied to a hosted project: a compensating migration that drops the P1 objects (forward-only policy, §P14).
