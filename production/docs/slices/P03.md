## How the swap works

- **Imports:** components keep importing `@/lib/data/repo`.
- **The swap:** with `DATA_SOURCE=supabase`, `next.config.ts` (`turbopack.resolveAlias`) points that specifier at `src/lib/data/supabase/repo.ts`. The mock (seed, store, fixtures) is then not in the bundle; `check:build --strict-proto` proves it, and CI now runs it strict.
- **Contract:** `src/lib/data/supabase/contract.check.ts` fails `tsc` if a UI-facing function is missing from either source or its type differs from the mock's. Every Supabase function is typed `typeof Mock.<fn>`. A negative control was run.
- **Mock stays:** it is the default for local dev and tests (`DATA_SOURCE` defaults to `mock` there and `supabase` when hosted; hosted + `mock` is refused). `npm run visual` / `e2e` still use it.

## Decisions (check these)

1. **Reads from the browser client under RLS, not Server Components** (deviation from the plan text).
   - The pages are client components. Next 16 docs say Server Functions are dispatched one at a time and meant for mutations.
   - Moving the reads into Server Components would mean restructuring the UI, which P3 forbids.
   - Reads therefore call SQL read functions (security invoker), which build the prototype's exact row shapes. P11 can move hot reads server-side with caching if the budgets need it.
2. **Writes are Server Actions → SECURITY DEFINER RPCs** (`src/lib/data/supabase/actions.ts`). Each action uses the caller's cookie session, and authorization stays in the RPCs and RLS, so a direct POST can't exceed the caller's role. `NetworkError` is preserved: an action returns `{network:true}`, and the client wrapper throws it.
3. **Minimum auth pulled forward from P4.** Without it, nothing can be read under RLS. Supabase password sign-in sits behind `login()`; there is also a cookie-presence `hasSession()` for the existing UI guard, plus `getProfile`, `updateDisplayName`, and `changePassword` (re-verify, `signOut({scope:"others"})`, `mark_password_changed`). **P4 still owns:** the proxy route guard, the real E1–E6 error mapping, lockout, and the full role model.
4. **Read policies = the P10 matrix read column.**
   - `authenticated` can select packages, crew, bookings, items, booking_crew and invoices.
   - On profiles, only `(id, display_name, role)` is readable. The own row's private fields come from `my_profile()`; `workspace_settings` only through `get_settings()`.
   - **Finding:** current Supabase does not grant the API roles table access by default, so migration 003 grants SELECT explicitly. The PGlite shim used to grant everything, which hid this; it now matches Supabase.
5. **Local users** are in `supabase/seed.local-users.sql` (one admin and one viewer account), loaded only by the local / CI stack. Hosted projects are never seeded with known passwords.
6. **New contract functions** (query-shaped, both sources): `listAllBookings(q)`, `countBookings()`, `peekProfile()`, `peekCatalog()` / `loadCatalog()`.
7. **Call sites changed, markup unchanged:**
   - **Bookings dashboard:** one parallel base load, then calendar rows and the table page re-query on filter change. The previous result stays on screen, and the list skeleton stays until its first result.
   - **Header:** `peekProfile` plus a load on mount.
   - **Role:** `useIsViewer` / `useIsAdmin` subscribe to the profile.
   - **Booking form:** waits for its catalog; on the mock it opens at once, as before.
   - **`setRole`:** moved next to `/dev/role`.
   - **Storage keys:** the `proto:` profile event and flash keys were renamed (not mock data).
8. **Crew order** is kept (`booking_crew.position`, in 001 / 002, which were never deployed). **Seed `created_at`** keeps the prototype's list order.
9. **Package RPCs** (`list_packages`, `save_package`, `archive_package`, `restore_package`) port `packageErrors` / `savePackage`; P5 owns the rest of US-0.

## Known gaps (owned later)

- **Calendar range (P6):** the calendar loads every row matching the filters, not only the visible range.
- **Logo (P8):** business logo is stored as the prototype's data URL in `business_logo_path`. P8 moves it to Storage `branding/`.
- **Seed names:** seeded rows' `createdBy` resolves to the local admin's display name, not the prototype's literal "Admin". `canceledBy` / `createdBy` are excluded from read parity for that reason.
- **Package counts:** `PackageRow.bookings` is the real count. The prototype showed Figma's legacy counts (P5).
