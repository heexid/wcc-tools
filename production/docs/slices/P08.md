## D4 (decided 2026-11-16, user): own table for now

Bank details (`default_payment`) and default terms (`default_terms`) come from this module's `workspace_settings` row through `getSettings()`. That one adapter can later read the Invoice module's Payment receiver instead. New bookings prefill both (`loadCatalog`, P3). PRD §5.3 Q3 is resolved.

**Changing bank details or terms (no edit screen in v1):** an admin runs in the SQL editor:

```sql
update public.workspace_settings set
  default_payment = '{"receiptName":"Bank BCA","accountNumber":"1234567890","accountName":"Your Studio"}',
  default_terms   = 'Remaining balance is due H-3 before the booking date. …';
```

The `default_payment` shape is enforced by a CHECK (receipt ≤ 60, account number 5–20 digits, account name ≤ 80); terms are limited to 255 characters. Existing invoices never change (below).

## Business information (US-14): logo moved to Storage

| Piece | How |
|---|---|
| Bucket | `branding`: private, PNG / JPEG, ≤ 1 MB (migration 010). Policies: staff read, admins write, through the same `is_staff()` / `is_admin()`, so the midnight rule and deactivation apply. |
| Save | The browser still re-encodes to ≤ 256 px. The Server Action re-validates the **bytes** (PNG / JPEG signature, ≤ 1 MB), uploads to `logo/<sha256>.<ext>`, and stores only the path. An unchanged logo keeps its path; removing it clears the path. |
| Read | `getBusiness()` / `getSettings()` return a 1 h signed URL in place of the path, so the card's `<img>` and the PDF use it exactly as they used the data URL. |
| Old files | Replaced logos stay in the bucket (content-named, tiny). Cleanup is a P13 job if ever needed. |

## Code review (2026-11-16, report-only, fixed by hand)

All 10 findings were real; all fixed:

| # | Finding | Fix |
|---|---|---|
| 1 | Signing the logo after a committed save could report "Couldn't save" | Signing never throws after the save; falls back to the image the user just picked |
| 2 | A missing logo object / Storage blip broke every settings read (booking form, dashboard) | `withLogoUrl` never throws: no URL → initials |
| 3 | Dashboard base load gave up after 3 retries | Keeps retrying every 10 s, like the lists |
| 4 | Mock vs SQL paging clamps differed (0, fractions, junk) | One rule in both (junk → default, floor, clamp 1–100); 4 new read-parity cases (72 / 72) |
| 5 | The booking trigger set `updated_at := now()` (transaction time), overriding the save's real time | Trigger and save use `greatest(clock_timestamp(), previous + 1 ms)` |
| 6 | Any CHECK violation was reported as "below paid" | Only the `bookings_total_covers_paid` constraint is mapped (by constraint name); others surface as themselves |
| 7 | The list retry timer could cancel its own in-flight attempt | The timer starts from the failure, so an attempt is never cut short |
| 8 | Replaced / removed logos were never deleted | The previous object is removed after a successful save (best effort) |
| 9 | A ≤ 1 MB logo in base64 exceeds Next's 1 MB Server Action body limit | `experimental.serverActions.bodySizeLimit: "2mb"` |
| 10 | Versions compared at ms precision → two saves in one ms looked identical | Every new version is ≥ 1 ms after the previous one |
