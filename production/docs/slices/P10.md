## Viewer enforcement

Every Server Action calls an RPC that starts with `require_admin()` (or `is_staff()` for the caller's own profile). The UI hiding buttons is not the control. Verified by the matrix and by the Supabase e2e "viewer" tests: no write controls, `/edit` → read-only, a direct Storage upload refused.

## PII (PRD §4.4)

- **Phone numbers** stay out of file names (`INV-…_{client-slug}.pdf`), URLs and logs.
- **The `wa.me` link** is built client-side from the phone on screen.
- **`src/lib/scrub.ts`** redacts phone numbers (+62 / 0… / 62… forms), emails, JWTs, Bearer tokens and signed-URL tokens; 8 unit tests. Every server log line goes through it. P13's Sentry `beforeSend` must use it.
- **Audit:** the only other log calls are client-side `NetworkError` lines, which carry an operation name only.

## Headers and cookies

| Item | Setting |
|---|---|
| CSP | `default-src 'self'`; scripts `'self' 'unsafe-inline'` (Next's inline bootstrap; no nonce pipeline yet); images / connections limited to `'self'` + the Supabase origin; `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`, `object-src 'none'`. Dev adds `'unsafe-eval'` and websockets. |
| Other headers | `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera / mic / geolocation / payment off), HSTS when hosted |
| Cookies | Auth cookies `Secure` when hosted, `SameSite=Lax`, path `/`. **Not HttpOnly, by design:** the browser client reads under RLS (P3 decision), so the database is the security boundary. |
| Server Actions | Next's built-in Origin / Host check; body limit 2 MB (logo upload) |
| Service-role key | Server-only (`server-only` modules); `check:build` fails if its **value** or its name appears in client JS (CI sets a placeholder to test the guard) |

## Whole-branch security review (2026-11-16)

**No findings** at confidence ≥ 8 across migrations 001–012, storage policies, the proxy, all Server Actions, the PDF route, headers, env / build guards and CI. Verified:
- Every SECURITY DEFINER function has `search_path` pinned and checks the caller first. Internal helpers are revoked from all API roles.
- Grants and RLS match the matrix. Roles can't be self-provisioned (only `app_metadata`).
- No open redirect, no SSRF / IDOR in the PDF route, no service-role exposure, no data-driven XSS sinks, no PII in server logs.
- A hosted build can't ship the mock or `/dev`. CI isn't exploitable by untrusted PRs.

Two minor notes, both closed:
1. The logo path is now constrained to `logo/<sha256>.(png|jpg)` by a CHECK (migration 010), so even an admin calling the RPC directly can't point the server at another object.
2. `/` redirected to `/dev`, which 404s in hosted builds; hosted builds now go to `/bookings`.
