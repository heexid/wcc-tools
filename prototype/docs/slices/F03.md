## Masks (Figma quirks, with reason)
- **E2 value text** — Figma draws the invalid email in placeholder grey (Input Error variant default); we keep typed text `text/primary`.
- **E3 / E5 password eye icon** — Figma's Password *Focus* variant shows eye-off although the value is hidden; we show the state-correct icon.

## Findings
- Stale dev-server SSR modules can cause hydration-mismatch "Issues" after editing shared components — the G3 issue detector caught it; restart `next dev` if a slice's first run shows an Issue on unchanged pages.
- Next.js mounts its own `role="alert"` route announcer — scope alert selectors in tests to the page content.
- Screenshots now move the mouse to (0,0) in `settle()` so a just-clicked button isn't captured in its hover state.
- Centred hug headings need `<Txt>` too (greeting heading) — same rule as F1.

## Motion
- `find-animation-opportunities`: 1 accepted — notice Alert entrance (occasional; preventing a jarring change). Rejected: card entrance on load (delays typing), shake on wrong password (redundant with alert + focus), inline errors / Caps Lock hint (keystroke feedback must be instant), route transition (core navigation).
- `animate`: `.motion-notice` in `motion.css` — `@starting-style` opacity + `translateY(−var(--list-from-y))`, `--dur-collapse` (200 ms) `--ease-out`, entrance only, re-keyed per notice; reduced motion = fade only. Reusable for Package 06, Bookings 23 / 37. Feel-check: alert fades while the card grows instantly — review at 3× in DevTools.
